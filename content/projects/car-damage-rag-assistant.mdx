## 프로젝트 개요

차량 손상 모델의 탐지 결과만으로는 사용자가 손상 부위를 확인한 이후 추가 촬영, 수리 전 점검, 보험 준비에 필요한 후속 조치를 판단하기 어렵습니다. 또한 운행 가능 여부나 수리비처럼 사진만으로 확정하기 어려운 질문에는 신중한 안내가 필요합니다.

이 프로젝트는 **차량 이미지에서 손상 유형과 위치를 분석하고, 해당 결과와 질문 목적에 맞는 대응 가이드를 제공하는 시스템**입니다. 손상 확인 이후 필요한 추가 촬영, 수리 전 점검과 보험 준비 과정을 안내하며, **근거가 부족하거나 안전 판단이 필요한 질문은 제한된 안내로 전환하도록 구성**했습니다.

## 트러블슈팅

### **01. 탐지 결과를 반영한 RAG 검색 파이프라인 개선**

#### **문제 상황**

**초기 RAG 검색은 사용자의 질문만 사용해 이미지에서 탐지된 손상 유형과 위치를 검색에 반영하지 못했습니다.** 이후 복수 query를 적용했지만 **동일한 chunk와 source가 반복되면서 검색 결과의 중복과 편중이 발생했습니다.**

#### **해결 과정**

##### **1. 검색 구성 비교 및 선정**

- 차량 손상과 후속 대응 정보를 21개 Markdown 문서로 구성하고 청킹 전략 3종과 E5 임베딩 모델 2종 비교
- 검색 품질과 지연시간을 비교해 최종 236개 chunk 구성과 multilingual-e5-small 선정

##### **2. 탐지 결과 기반 검색 정제**

- analysis_id로 조회한 손상 유형 및 위치와 질문 Intent를 결합해 복수 retrieval query 생성
- 검색 결과 병합 후 동일한 chunk를 제거하고 Intent·손상 유형·문서 우선순위에 따라 재정렬
- source당 최대 2개, 최종 최대 5개 chunk로 제한해 중복과 특정 문서 편중 완화

##### **3. 서비스와 평가 흐름 일치**

- 실제 서비스의 탐지 결과 조회, 복수 query, 중복 제거와 재정렬 로직을 평가에서도 동일하게 사용
- 23개 회귀 질문을 대상으로 Section Hit Rate, MRR, MAP과 검색 지연시간 검증


#### **결과**

임베딩 모델 비교에서 multilingual-e5-small은 multilingual-e5-base 대비 **Section Hit Rate 69.57% → 91.30%로 21.73%p 향상**됐습니다. 탐지 결과와 Intent를 반영한 최종 검색 파이프라인에서는 **MRR 0.84, MAP 0.57**을 기록했습니다.


### **02. 유사 질문의 Intent 혼동과 안전 답변 제어**

#### **문제 상황**

차량 손상 질문은 표현이 비슷해도 추가 촬영, 보험 제출, 수리 전 점검처럼 질문 목적이 다릅니다. **초기에는 보험 제출 질문이 일반 촬영 질문으로 분류되거나, 운행 가능 여부·수리비처럼 사진만으로 확정하기 어려운 질문이 일반 답변 생성 경로로 전달되는 문제가 있었습니다.**

#### **해결 과정**

##### **1. Intent 분류 기준 보완**

- 질문 목적을 손상 설명, 심각도 해석, 추가 촬영, 보험 제출 자료, 보험 판단에 필요한 확인 항목, 수리 전 점검의 6개 지원 Intent로 구분
- 범위 밖이거나 안전 판단·수리비·보험 결과처럼 사진만으로 확정하기 어려운 질문은 Fallback으로 분리
- 보험 제출과 일반 촬영 질문의 구분 기준을 추가하고, 확정하기 어려운 질문을 우선 검사하도록 분류 순서 조정

##### **2. LangGraph 답변 경로 분리**

- 질문 검증, 탐지 결과 조회, 문서 검색, 근거 판단, 답변 생성과 Fallback을 개별 node로 구성
- 지원 가능한 질문은 검색과 답변 생성으로 연결하고, 안전 판단이나 사진만으로 확정하기 어려운 질문은 conditional edge를 통해 Fallback으로 분기

##### **3. 회귀 테스트 적용**

- 기존에 혼동이 발생한 추가 촬영·보험 제출·안전 질문을 회귀 테스트로 구성
- 분류 규칙 수정 후 각 질문이 의도한 Intent와 Fallback 경로로 전달되는지 검증

#### **결과**

**Intent 분기 회귀 테스트 35/35, Safety Fallback 경로 검증 7/7을 통과**했으며, 추가 촬영과 보험 제출 질문을 구분하고 사진만으로 확정하기 어려운 질문은 일반 답변 생성 경로에서 제외했습니다. 해당 수치는 기존 오류 문항을 중심으로 수정 사항의 재발 여부를 확인한 회귀 테스트 결과입니다.

## 향후 고도화 방향

현재는 차량 손상 탐지 결과와 문서 검색을 연결하는 로컬 프로토타입으로 구현했습니다. 향후에는 독립 질문 세트를 활용해 검색과 Intent 분류의 일반화 성능을 검증하고, reranker 적용을 통해 검색 결과의 우선순위를 정교화할 수 있습니다. 또한 영속 저장소와 다중 사용자 요청 처리 구조를 추가해 실제 서비스 형태로 확장할 수 있습니다.

## 회고 및 배운점

RAG 검색을 구성하면서 사용자 질문만으로 검색할 때보다 이미지에서 탐지된 손상 정보와 질문 목적을 함께 활용하면 검색 대상을 더 구체화할 수 있다는 점을 배웠습니다. 또한 복수 query를 사용할 경우 검색 범위는 넓어지지만 동일한 chunk와 source가 반복될 수 있어 중복 제거와 재정렬 과정이 함께 필요했습니다.

검색 품질은 기대 문서의 포함 여부뿐 아니라 문서의 순위와 불필요한 결과까지 함께 평가해야 했습니다. 또한 LangGraph로 질문 범위와 검색 근거에 따라 답변 경로를 분리하면서, 답변 품질뿐 아니라 근거가 부족하거나 안전 판단이 필요한 상황에서 답변 생성을 제한하는 구조도 중요하다는 점을 배웠습니다.
