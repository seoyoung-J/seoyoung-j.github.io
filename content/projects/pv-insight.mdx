## 프로젝트 개요

태양광 발전소는 넓은 구역에 많은 패널이 설치되어 있어 모든 패널을 정기적으로 점검하려면 많은 시간과 인력이 필요합니다. 이미지 분석으로 이상 가능성이 높은 구역을 먼저 선별해 관리자가 우선 확인할 대상을 좁힐 수 있도록 하는 것을 목표로 했습니다.  

RGB와 열화상 이미지는 확인할 수 있는 이상 유형이 달라 각각 별도의 모델로 분석합니다. **RGB 이미지에서는 파손, 식생 침범, 오염, 패널 누락, 음영의 5개 외관 이상을 분석하고 열화상 이미지에서는 국부 과열, 다이오드 동작 이상, 패널 연결 구간 고장의 3개 유형을 분석**합니다.

분석 결과는 bounding box와 mask로 시각화하고, 이상 유형에 따라 청소, 재촬영, 현장 점검, 교체 검토 등의 유지보수 조치 후보를 제공합니다.

## 담당 역할

**RGB 세그멘테이션 모델링**

- YOLOv26s-seg 기반 RGB 5개 클래스 모델의 입력 해상도, 라벨 정제, fine-tuning 조건 비교 및 작은 결함 탐지 성능 개선
- 26개 checkpoint의 전체 및 클래스별 성능을 동일 Validation 조건에서 비교해 최종 모델 선정

**ONNX 추론 및 FastAPI AI Worker 구현**

- PyTorch 최종 모델을 raw FP32 ONNX로 변환하고, ONNX Runtime 기반 bounding box 및 instance mask 후처리와 정합성 검증
- SQS 메시지 수신·검증, 분석 Job 상태 전환, 결과 저장 및 메시지 삭제 로직을 포함한 FastAPI AI Worker 구현

**백엔드 및 비동기 분석 연동**

- Spring Boot 기반 이미지 등록, 분석 Job 생성·조회, 분석 결과 조회 API 구현
- Spring Boot의 SQS 메시지 발행과 FastAPI AI Worker 처리를 연결해 비동기 분석 흐름 구현

## 트러블슈팅

### **01. 고해상도 이미지의 작은 결함 탐지 성능 개선**

#### **문제 상황**

원본 RGB 이미지는 평균 약 2000px의 고해상도였지만, AWS 기반 추론 환경의 메모리 사용량과 처리 비용을 고려해 입력 해상도를 낮춰야 했습니다. 이 과정에서 **식생 침범과 파손처럼 작은 이상 영역의 미탐이 두드러져 전체 mask 성능과 클래스별 성능 개선이 필요했습니다.**

| 식생 침범 mask recall | 0.41 | 0.57 | +16.0%p |

#### **추가 실험**

성능 개선 가능성을 검토한 추가 실험과 적용에 제외한 사유는 아래와 같습니다.

- Slicing Aided Hyper Inference (SAHI) 기반 타일 추론 — 처리 시간이 약 3배 증가해 서비스 적용에서 제외
- 패널 어레이 기반 동적 crop 추론 — 이미지당 평균 13.6회의 반복 추론이 필요해 제외
- 오염(dusty) 클래스 개선 실험 — dusty 1-class 분리와 5-class 라벨 정제를 비교했으나 성능 개선이 없어 제외
- 파손(broken) 클래스 보강 fine-tuning — recall은 상승했지만 precision과 종합 성능이 하락해 제외


### **02. ONNX 원시 출력 후처리 오류 해결 및 추론 정합성 검증**

### **추가 검증: 정적 INT8 양자화(Static Post-Training Quantization, PTQ)**

재학습 없이 FP32 ONNX의 배포 아티팩트 크기와 CPU 추론 효율을 개선할 수 있는지 확인하기 위해 정적 PTQ를 적용했습니다. **아티팩트 크기는 71.8% 감소**했지만 Mask Recall은 6.5%p, mAP50은 2.8%p 하락했고 평균 E2E latency는 29.4% 증가해 **INT8은 최종 적용하지 않았습니다.**

## 회고 및 배운점

작은 이상 영역은 전체 평균 지표만으로 문제를 확인하기 어려워 클래스별 Recall과 예측 결과를 함께 확인해야 했습니다. 입력 해상도와 라벨 품질을 조정하고 SAHI와 동적 crop 방식까지 비교하면서, 성능이 개선되더라도 반복 추론 비용이 커지면 서비스에서는 적용하기 어렵다는 점을 확인했습니다.

또한 ONNX 변환은 속도 향상을 전제로 판단하지 않고 변환 전후의 성능 정합성, 아티팩트 크기와 실제 CPU latency를 함께 비교했습니다. INT8도 아티팩트 크기는 크게 줄었지만 Recall과 latency가 악화되어 적용하지 않았습니다. SQS 기반 비동기 처리에서는 모델 추론뿐 아니라 Job 상태 전이와 메시지 삭제 순서가 중복 실행과 재시도 동작에 직접 영향을 준다는 점을 확인했습니다.
